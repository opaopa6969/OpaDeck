# OpaDeck 市場調査

## 0. 要約

立ち位置: 完成品のローコード製品ではなく、既存の社内APIアプリに埋め込む依存ゼロの operation-centric ランタイムである。

最大の弱点: npm公開・ライセンス明記・ブラウザの自動スモークテストがなく、採用判断の入口で完成品と比較されると不利である。

次の一手: 実アプリ1件を「定義から操作画面まで」の再現可能なサンプルにし、DSLの不足部分と配布契約を埋める。

## 1. このrepoは何か

OpaDeck は、HTTP API を操作する社内向け画面を、`AppDefinition`（group / operation / field / request / result / layout / help）から組み立てるブラウザ用 ESM ライブラリである。実装上は `createWorkbench` が nav → detail/form → results の3面シェルを配線し、`createHttpExecutor` が入力を request preview に変換して注入された `fetch` で実行する。`src/index.js` はランタイム、DSL、レンダラ、地図、ツアーを再exportしている。

提供価値は、APIごとの管理画面で毎回手書きしていた入力フォーム、リクエストプレビュー、実行履歴、結果表示、ヘルプ／ツアー、選択状態の配線を、安定したIDと検証可能な定義に寄せることだ。前段にアプリ開発者とAPI定義、後段に既存のブラウザアプリとバックエンドAPIがあり、OpaDeck単体ではログイン、永続DB、ユーザー管理、ホスティングは提供しない。

想定利用者は、既存の社内業務システムに、開発者向けの操作面・データ検証面・地図結果面を組み込みたいチームである。ノーコードで新規アプリを作りたい利用者より、コードと既存のデプロイ基盤を保持したい利用者に合う。

確認できた客観指標は、Node.js >=18、外部依存パッケージ数 0、`src` 35 JavaScript files、tests 15 files、`npm test` 71 tests passed、リポジトリ容量 1.7M（作業ツリー、`.git`除外）である。公開URL・npm公開・ライセンスファイルはこの調査時点で確認できず、GitHub star数も確認できない。

READMEだけでなく `docs/en/IMPLEMENTATION.md`、`CORE_MODEL.md`、`EXTENSIONS.md`、`src/index.js` とテストを確認した。URL state は作業ツリーに追加済みで、DSLの layout/help/tour ブロックも実装・テスト済みである。

## 1.5 調査の型

`library` と判定した。OpaDeck自身がブラウザに組み込むコードで、サーバーやホスト型サービスではないため、比較軸は機能の数だけでなく、APIの宣言性、拡張点、依存の重さ、テスト可能性、配布のしやすさである。

なお、実利用価値は「OpaDeck + 利用側アプリ + HTTP API」の組み合わせで出る。しかし比較対象をライブラリだけに狭めると利用者の置き換え判断を誤るため、同じ社内操作アプリを丸ごと作る Appsmith / ToolJet / Budibase と、組み込み型の react-admin を併記した。完成品3製品は実装コードも公開されているが、OpaDeckとのAPI粒度が異なるため、4.5では依存・構成の事実を比較し、機能優劣は4節で分けて読む。

## 5.5 調査者の見立て

本当の勝負所は、完成品との機能数差ではなく「既存の業務アプリへ、operationの意味・HTTP送信・結果・説明を同じ定義から埋め込めるか」だと思う。OpaDeckのrequest previewと検証は、単なるフォーム部品より明確な理由になりうる。

数字に出ていない懸念は、採用者が最初に見る配布契約が未完成なことだ。private package、ライセンス、型定義、ブラウザの実動作確認が見えないままだと、依存ゼロの利点が「未成熟」に読み替えられる。

私なら、次の四半期は認証や50個のconnectorを作らず、実在するAPI操作アプリを1件、DSLまたはJSONから再現可能にして、npm相当の配布とブラウザ smoke test を先に固める。

この見立てが外れる条件は、利用者が既存画面への埋め込みより、非開発者による新規業務アプリ作成を主に求める場合である。その場合はAppsmith等のbuilderが本質的に優位で、OpaDeckの依存ゼロは採用理由にならない。また、react-adminが素のDOM／非React利用とAPI操作previewを標準で満たした場合も、差別化は縮む。
